# 약 복용 일지

- 작성일: 2026년 11월 9일
- 상태: 주요 동작의 모호한 표현 검토 및 사용자 선택 반영 완료.
- 이번 결과물은 기획서이며 HTML은 아직 제작하지 않습니다.

## 대상 사용자

- 나와 가족이 각자 안드로이드 스마트폰에서 사용합니다.
- 각자 자기 휴대폰에서 본인의 약과 기록만 관리합니다.

## 사용 목적

- 먹어야 할 약과 복용 시각을 한눈에 확인합니다.
- 복용 여부를 기록하여 먹었는지 헷갈리는 일을 줄입니다.
- 지난 복용 기록을 날짜별로 확인합니다.
- 하루의 몸 상태와 약별 특이사항을 메모합니다.

## 화면 구성과 동작

| 화면 | 구성과 동작 |
|---|---|
| 오늘의 복용 | 오늘 예정된 약을 시각 순서로 표시하고 완료·남은 복용 횟수를 보여줍니다. |
| 약 등록·관리 | 약 이름, 1회 복용량, 복용 시각 여러 개, 복용 관련 메모, 시작일·종료일을 입력합니다. |
| 지난 기록 | 달력에서 날짜별 현황을 보고, 날짜 선택 시 약·실제 복용 시각·메모를 확인합니다. 주간·월간 목록도 제공합니다. |
| 메모 | 하루 전체 메모와 약별 복용 메모를 작성·수정합니다. |
| 화면 알림 | 페이지가 화면에 열려 있을 때 예정 시각에 알림을 표시합니다. 늦게 열면 오늘 시각이 지난 미복용 약을 모아서 안내하고 목록에서도 강조합니다. |

### 기록과 일정 규칙

- 처음에는 빈 목록으로 시작하고 사용자가 직접 약을 등록합니다.
- 매일 정해진 시각의 복용과 기간을 지정한 복용을 지원합니다. 특정 요일별 일정은 이번 필수 범위에 포함하지 않습니다.
- 시작일은 필수이고 종료일은 선택입니다. 종료일이 없으면 중단 전까지 계속 복용하는 일정입니다.
- 같은 약에 하루 여러 복용 시각을 등록할 수 있습니다.
- 약별 각 예정 복용 건을 개별 체크합니다. 체크 전에는 ‘미복용’으로 표시합니다.
- 오늘 복용을 체크하면 현재 시각을 실제 복용 시각으로 자동 입력합니다. 지난 날짜 기록에는 실제 먹은 시각을 직접 입력하거나 ‘시각 미상’을 선택합니다. 시각 미상도 복용 완료로 집계합니다.
- 체크 취소 시 실제 복용 시각 또는 시각 미상 표시를 지우고 미복용으로 되돌립니다. 약별 메모는 유지합니다.
- 완료·남은 개수는 알약 수나 약 종류 수가 아닌 약별 예정 복용 횟수로 계산합니다.
- 예: A를 08:00·13:00·19:00, B를 09:00에 등록하면 총 4회입니다. B를 한 번에 2정 먹어도 1회입니다.
- 필요할 때 먹는 약은 먹을 때마다 별도로 기록하고, 예정된 완료·남은 횟수에서 제외합니다.
- 약 정보 수정·중단 시 적용 날짜를 직접 선택합니다. 오늘을 선택하면 아직 복용하지 않은 일정부터 적용하며, 이미 완료한 기록과 과거 기록은 당시 정보로 유지합니다. 미래 날짜를 선택하면 그날부터 변경·중단을 반영합니다.
- 적용일을 오늘 이후 날짜로 제한하는 방안은 제안 상태이며, 과거 적용일 허용 여부는 구현 전 확인합니다.
- 오늘 중단 시 오늘의 완료 건은 목록과 횟수에 남기고, 미복용 예정 건은 제외합니다. 미래 적용일 중단 시 해당 날짜부터 예정 목록·횟수에서 제외합니다. 중단 전 기록은 유지합니다.
- 지난 날짜의 복용 기록·시각·메모를 추가하거나 수정할 수 있습니다.
- 상태는 색상과 글자를 함께 사용해 구분합니다.
- 이름·1회 복용량·시작일은 필수, 메모·종료일은 선택입니다. 정기약은 예정 시각도 필수이며 필요시약은 예정 시각 없이 등록합니다.
- 필수 입력 누락, 종료일이 시작일보다 빠른 경우, 같은 약에 동일한 예정 시각을 중복 입력한 경우에는 이유를 안내하고 저장을 막습니다.
- 기록은 현재 기기와 브라우저에 자동 저장합니다.

### 알림·조회 규칙

- 화면 알림은 닫기 버튼을 누르기 전까지 표시합니다. 닫아도 복용 완료로 처리하지 않으며 직접 체크해야 완료됩니다.
- 페이지를 다시 열 때마다 오늘 예정 시각이 지난 미복용 약을 모아서 안내합니다. 알림을 닫아도 목록 강조는 유지합니다.
- 달력은 예정된 약의 복용 현황을 ‘완료 2/4회’처럼 숫자와 상태 색상으로 표시합니다. 필요시약은 분모·분자에서 제외하고 날짜별 상세에서 확인합니다.
- 주간 조회는 월요일-일요일, 월간 조회는 해당 월 1일-말일입니다.

## 필요한 자료

- 사용자가 직접 입력하는 약 이름, 1회 복용량, 복용 시각, 복용 관련 메모, 시작일·종료일.
- 사용자가 남기는 복용 여부, 실제 복용 시각, 하루 메모, 약별 메모.
- 검증용 가상 약 정보는 아래 검증 방법에 기재합니다.
- 외부 의약품 자료, 사진, 외부 글꼴·라이브러리는 사용하지 않는 구성으로 기획합니다. 별도 외부 자료의 출처·사용 권한 표기는 해당 없습니다.

## 추가 기능

- 페이지를 닫은 뒤에도 받는 휴대폰 알림: 이번 화면 알림과 분리하여 이후 별도 구현 단계에서 실행 방식과 필요한 환경을 검토합니다.

## 한계 및 비목표

1. 기록은 각자의 기기·브라우저에만 저장합니다. 가족 간 공유, 기기 간 동기화, 로그인, 백업·복원은 이번 범위에서 제외합니다. 브라우저 데이터를 삭제하면 기록이 사라질 수 있습니다. 로컬 HTML의 저장 유지 여부는 실제 사용할 기기·브라우저에서 검증합니다.
2. 필수 알림은 페이지가 화면에 열려 있는 동안의 화면 알림입니다. 소리 알림은 포함하지 않으며, 페이지를 닫거나 다른 앱으로 전환하거나 화면을 잠근 상태의 알림은 보장하지 않습니다.
3. 사용자가 입력한 내용을 기록·조회하는 도구입니다. 외부 의약품 정보 조회, 약 사진, AI 상담, 복용량·복용 방법의 적절성 판단은 구현하지 않습니다.

## 검증 방법

### 비교 대상과 절차

가상 약과 복용 일정을 등록하고 수기로 작성한 예상 목록·복용 횟수·기록을 실제 화면 결과와 비교합니다. 실제 약 복용 없이 테스트용 정보로 진행합니다. 아래 25개 테스트를 개발 중 확인과 실제 안드로이드폰 확인으로 나누어 수행하고 결과 상태를 기록합니다. HTML은 아직 구현하지 않았으므로 모든 테스트는 미실행입니다.

### 실행 환경과 판정 규칙

- 실제 사용할 안드로이드폰 모델·운영체제·브라우저 이름과 버전, HTML 파일명·위치, 테스트 날짜를 기록합니다. 일반 모드에서 같은 파일로 검증합니다.
- 결과는 ‘미실행·통과·실패·판정 보류’ 중 하나로 기록합니다. 한 테스트 안에 여러 절차가 있으면 모두 확인해야 통과입니다.
- 준비 데이터·기능·확정 기준이 없어 판단할 수 없으면 판정 보류로 남기고 이유를 적습니다. 실행하지 않은 항목은 미실행이며 실패로 간주하지 않습니다.
- 알림 표시 허용 지연은 10초 이내를 제안합니다. 10초는 아직 확정하지 않은 제안값이므로 실제 지연을 측정하되 그 수치만으로 최종 합격·불합격을 정하지 않습니다.
- 알림 유지 테스트는 60초 관찰 후 닫기를 제안합니다. 기능 요구는 ‘닫기 전까지 유지’이며, 60초 관찰은 제한된 표본 검증입니다. 관찰 시간은 확정 전 제안값으로 기록합니다.
- 미래 일정의 생성·변경·중단은 개발 검증에서 기준 날짜를 지정해 확인합니다. 이는 검증 코드의 날짜 지정이며 사용자용 날짜 조작 기능을 추가하는 요구가 아닙니다.
- 미래 일정을 화면으로 미리 조회하는 기능은 아직 확정하지 않았습니다. 미리보기가 없다면 실제 폰에서는 다음 날 다시 열어 적용을 확인합니다. 휴대폰의 시스템 날짜는 변경하지 않습니다.
- 개발 중 날짜 지정 검증을 통과해도 실제 폰의 재실행·알림·날짜 전환 검증을 대신하지 않습니다. 필요한 실제 확인이 남아 있으면 해당 테스트는 통과로 마감하지 않습니다.

| 테스트약 B | 매일 09:00 | 2정 | 시작일 오늘, 종료일 없음 |

- 기본 예상: 오늘 예정 총 4회, 초기 완료 0회·남음 4회.
- 1~5번은 순서대로 진행합니다. 3번은 A의 08:00과 B의 09:00을 체크하고, 4번은 B 체크를 취소합니다.
- 알림·일정 변경·기간 테스트는 별도 가상 약으로 진행하여 기본 횟수 비교에 영향을 주지 않게 합니다.
- 6번에서 필요시약 기록을 추가하기 전후의 예정 완료·남은 횟수를 기록해 동일한지 비교합니다.
- 15번은 기본 A·B의 완료가 2/4회인 상태를 별도로 준비합니다. 4번 이후 상태를 그대로 사용한다면 B 09:00을 다시 체크해야 합니다. 필요시약 추가가 분모·분자를 바꾸지 않는지도 확인합니다.
- 8·19번은 시작일을 어제 또는 검증 대상 날짜 이전으로 둔 정기약을 먼저 준비하고, 그 날짜의 예정 건에 복용 기록을 추가합니다. 필요시약은 별도로 검증합니다.
- 9번은 시작일을 어제로 둔 별도 약을 등록하고 어제 복용·메모를 기록합니다. 오늘 일정 중 1건은 완료, 다른 1건은 미복용으로 둔 뒤 변경하여 어제·오늘 완료 건·오늘 미복용 건을 각각 비교합니다.
- 22번의 날짜 예시는 고정된 검증 데이터입니다. 실제 테스트 날짜가 달라도 같은 범위로 확인하며, 해당 날짜를 포함하는 시작일로 가상 약을 준비합니다.
- 테스트 데이터는 별도 가상 약과 날짜로 구분하며 다른 테스트가 예상 횟수를 바꾸지 않게 합니다. 사용자 실제 기록을 지워 테스트하지 않습니다.
